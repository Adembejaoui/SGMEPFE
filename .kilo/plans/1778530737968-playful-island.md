# Plan: Add Intervention Page for Technicien

## Overview
The goal is to add a dedicated **Intervention page** for the `TECHNICIEN` role that displays only the demandes (maintenance requests) that the logged-in technician has claimed (i.e., where `technicianId` matches the current user's ID).

## Current State
- The existing `DemandesTechnicienClient` component (`components/demandes/DemandesTechnicienClient.tsx`) shows **all** demandes available to the technician (with compatibility checks), not just the ones they've claimed.
- The sidebar (`components/dashboard-sidebar.tsx`) already has a "Mes interventions" menu item pointing to `/dashboard/technicien/interventions` (line 127).
- The `Intervention` type exists in `types/demande.ts` (line 166-170) but is minimal — only `idIntervention`, `demandeId`, `createdAt`, `updatedAt`.
- There is **no** dedicated API route for interventions yet.
- The Prisma schema has the `Intervention` model (stub) linked to `DemandeMaintenance` via `demandeId`.

## Tasks

### 1. Update `Intervention` Type (`types/demande.ts`)
- Extend the `Intervention` type to include `description` and `statut` fields so interventions can carry meaningful data.
- Add `InterventionWithRelations` type that includes the linked demande and technician info.

### 2. Create API Route: `app/api/interventions/route.ts`
- **GET**: List all interventions where the logged-in technician is assigned.
  - Filter by `technicianId` matching the session user (for TECHNICIEN role).
  - Include relations: `demande` (with equipement and client info).
  - Support pagination (`page`, `limit`) and optional `statut` filter.
- **POST**: Create a new intervention record for a demande the technician has claimed.
  - Validate `demandeId`, `description`.
  - Ensure the demande's `technicianId` matches the session user.

### 3. Create API Route: `app/api/interventions/[id]/route.ts`
- **PUT**: Update an intervention's statut/description.
  - Only the assigned technician can update.
- **DELETE**: Remove an intervention (ADMIN only or assigned technician).

### 4. Create Hook: `hooks/useInterventions.ts`
- SWR hook similar to `useDemandes` but for interventions.
- Fetches from `/api/interventions`.
- Returns `{ interventions, isLoading, error, mutate, pagination }`.

### 5. Create Component: `components/interventions/InterventionsTechnicienClient.tsx`
- Client component displaying the list of interventions (claimed demandes) for the current technician.
- Pattern follows `DemandesTechnicienClient.tsx`.
- Table columns: Demande #, Equipement, Description, Priorité, Statut, Date.
- Each row links to the intervention detail page (`/dashboard/technicien/interventions/[id]`).

### 6. Create Page: `app/dashboard/technicien/interventions/page.tsx`
- Server page that:
  - Auth check (redirect to login if not authenticated).
  - Role check (redirect if not TECHNICIEN).
  - Renders `InterventionsTechnicienClient`.

### 7. Update Sidebar (optional)
- The "Mes interventions" item already exists in `menuByRole.TECHNICIEN` (line 126-129) pointing to `/dashboard/technicien/interventions`. Verify the icon is appropriate (ClipboardList is already set).

## Key Design Decisions
- **Filtering by technicianId**: The GET `/api/interventions` endpoint filters server-side by `technicianId` from the session, ensuring technicians only see their own interventions.
- **Reuse existing patterns**: All API routes follow the same structure as `app/api/demandes/route.ts`. Components follow `DemandesTechnicienClient.tsx` patterns.
- **Statut flow**: Technicians can update intervention status (e.g., EN_COURS → TRAITEE) via the PUT endpoint, mirroring the demande status transition logic.
